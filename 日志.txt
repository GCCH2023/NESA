	要分析函数的参数和返回值，必须先知道它调用的函数的参数和返回值。
比如：
函数A ：
	CALL B
函数B：
	return a
	其中，a 是寄存器。
	显然，a 是函数B的参数，因为函数B没有对 a 赋值就使用了，从而可以推出，
a 也是 函数A 的参数。
	如果不知道函数B是否有参数，则无法确定函数A是否有参数。

注意：函数之间可能存在环状调用关系，比如：A调用B，B调用A
目标：确定每个函数的分析顺序，以分析函数的参数和返回值

	按函数深度来分析，如果一个函数没有调用任何函数，则它的深度是0，最先分析;
否则，函数的深度为它调用的函数的最大深度加一
问题：
	给定一个有向图，如果 节点A 有一条到 节点B 的边，表示节点A依赖于 节点B。
求一个节点序列，这个序列满足：
1. 图的所有节点至少要出现一次
2. 如果 节点A 依赖于 节点B，则 节点B 位于 节点A 前面
	不对，“求”这里有问题。

迭代分析法：
一直迭代：
	分析每个函数，确定它的参数和返回值：
	（1）对于所有非函数调用指令，如果这条指令使用了某个寄存器，并且使用前没有赋值，
	则将这个寄存器作为这个函数的一个参数；
	（2）对于函数调用指令，获取调用的函数的参数信息，如果某个参数传递前未赋值，则
	将这个参数作为这个函数的一个参数；
	返回值
直到所有函数的参数和返回值都保持不变

(4) 回到数组类型的格式化，格式化数组长度到已有字符串的后面，输出 [5]，得到 int (*p)[5];

2025-3-29
	新的问题：函数A内部包含另一个函数B，并且函数B还会跳转到函数A的开始指令。
	目前的函数范围识别算法：认为函数是连续指令组成的，从函数开始地址开始，
一直识别，直接遇到最后一个函数返回指令。
	处理方法：
1. 当作两个函数，并且它们的代码完全相同，需要修改函数范围识别算法，并且函数
范围会有问题。
2. 拆分成两个函数，函数A内联函数的部分改为调用函数B，函数B跳转到函数A的语句改为调用函数A，
需要修改指令，并且判断要不要修改。
	内联函数的判断：
（1）在识别一个函数时，如果这个函数的地址包含在数据库中存在的函数范围内且不是函数开始地址，则它是内联函数；
（2）在识别函数范围时，如果跳转地址在函数之前，那么就认为当前函数是内联函数；
（3）在识别函数范围时，如果一条指令属于数据库中存在的一个函数，说明当前函数内联了数据库中的函数。
	运用上面的3点，可以总结出函数范围识别算法：
a. 用给定函数地址查找数据库，如果存在一个开始地址为指定地址的函数，说明分析过了，返回这个函数；
b. 如果给定地址属于一个函数A的内部，说明这是一个内联函数，通常这个函数的范围是给定地址到函数A的结尾地址，
不属于这种情况，则报错；
c. 查找数据库中给定地址的下一个函数F，如果存在，则当前函数包含的指令最多到函数F的开始地址之前；否则，
当前函数的范围没有限制。
	如果存在函数F，并且当前识别的函数可以跳转到函数F的开始地址，则说明函数F是当前函数的内联函数。
如果当前函数跳转到其他地方，报错。

PPU_ADDR = A
PPU_ADDR = 0
(1) 先构建DAG，对第一条指令，将 PPU_ADDR 附加到 A节点:  varMap[PPU_ADDR] = A

① PPU_ADDR 查表获得对应的 0 节点，创建 0 节点，生成 PPU_ADDR = 0的语句；
② PPU_ADDR  查表获得对应的 0 节点，创建 0 节点，生成 PPU_ADDR = 0的语句。
结果；
PPU_ADDR = 0;
PPU_ADDR = 0;

解决方法：
（1） 保留变量时，同时保留变量对应的节点；
（2）在构建DAG，保留变量的同时生成C代码。
